# منصة تدريب الأولمبياد العلمي السوري — درعا

منصة تدريب لطلاب الأولمبياد العلمي السوري، **لأي اختصاص**: تختار الاختصاص من الإعدادات (الرياضيات، الفيزياء، الكيمياء، علم الأحياء، المعلوماتية، العلوم النووية، أو اسماً تكتبه). مبنية على منصة الإيفاد نفسها (التصميم، الاختبارات، الوظائف، الاستبيانات، الحضور، التقارير، الإشعارات، النسخ الاحتياطي)، مع:

- **المحاضرات العلمية:** ثلاث مراحل، ولكل مرحلة كلمة سر، وقائمة طلاب مسموح لهم، ومحاورها الأربعة (الهندسة، الجبر، التحليل التوافقي، نظرية الأعداد)، وأسئلة دوراتها، واختباراتها التجريبية.
- **رفع الملفات:** HTML تفاعلي، أو PDF يبقى PDF، أو PDF يُحوَّل إلى صفحة HTML بهوية المنصة.
- **الطلاب:** استيراد من Excel أو HTML أو CSV، وتوليد اسم مستخدم وكلمة سر ورقم امتحاني لكل طالب، وبطاقة دخول تُصدَّر صورةً أو نصاً.
- حُذف قسم «المسارات والأهداف». والاختبارات التجريبية داخل المراحل فقط، لا في القائمة الجانبية.

**تطوير وإشراف:** المهندس أسامة ياسر الصلخدي.

**البنية:** الواجهة ملفات ثابتة على GitHub Pages دون أي بناء. البيانات والحسابات والملفات على Supabase بالخطة المجانية. الحماية داخل قاعدة البيانات عبر RLS.

---

## جرّبها أولاً على جهازك (الوضع التجريبي)

ما دام `js/config.js` يحوي القيم الوهمية، تعمل المنصة ببيانات تجريبية داخل المتصفح فقط.

```bash
cd olympiad-math
python3 -m http.server 8000
```
ثم افتح `http://localhost:8000`.

| الحساب | اسم المستخدم | كلمة المرور |
|---|---|---|
| المطور | `dev` | `dev12345` |
| مشرف | `admin` | `admin123` |
| طلاب | `student1` … `student12` | `123456` |

الأرقام الامتحانية التجريبية من `1001` إلى `1012`. كلمات سر المراحل التجريبية: `1111` و`2222` و`3333` (الثالثة مغلقة).

## الإعداد خطوة بخطوة

### 1) إنشاء مشروع Supabase وتشغيل قاعدة البيانات
1. ادخل https://supabase.com واضغط **New project**.
2. اكتب اسماً مثل `olympiad-math`، وكلمة سر قوية لقاعدة البيانات واحفظها. اختر المنطقة **Central EU (Frankfurt)**، ثم **Create new project** وانتظر دقيقتين.
3. افتح **SQL Editor ← New query**.
4. انسخ محتوى `supabase/schema.sql` كاملاً والصقه، ثم **Run**. يجب أن تظهر **Success**.

الملف آمن لإعادة التشغيل ولا يحذف بيانات. وهو ينشئ أيضاً مخزني الملفات `submissions` و`materials`.

### 2) إيقاف التسجيل الذاتي وإنشاء حسابك (المطور)
1. **Authentication ← Sign In / Providers**: أطفئ **Allow new users to sign up** واحفظ.
2. **Authentication ← Users ← Add user ← Create new user**:
   - Email: `dev@olymp.local`
   - Password: كلمة قوية.
   - فعّل **Auto Confirm User**.
3. في **SQL Editor** نفّذ:
   ```sql
   insert into public.profiles (id, username, name, role)
   select id, 'dev', 'المهندس أسامة ياسر الصلخدي', 'dev' from auth.users where email = 'dev@olymp.local'
   on conflict (id) do update set role = 'dev';
   ```
تدخل بعدها باسم المستخدم `dev`. المنصة تحوّل كل اسم مستخدم داخلياً إلى `اسم@olymp.local`.

### 3) نشر Edge Function
1. **Edge Functions ← Deploy a new function ← Via Editor**.
2. الاسم بالضبط: `admin-users`.
3. الصق محتوى `supabase/functions/admin-users/index.ts` ثم **Deploy function**.

هذه الدالة هي التي تنشئ الحسابات وتغيّر كلمات السر. مفتاح `service_role` يبقى داخلها ولا يظهر في الواجهة.

### 4) ربط الواجهة (`js/config.js`)
1. **Project Settings ← API Keys** (أو زر **Connect**).
2. انسخ **Project URL** والمفتاح **publishable** (أو **anon public**).
3. ضعهما في `js/config.js`:
   ```js
   export const SUPABASE_URL = 'https://abcdxyz.supabase.co';
   export const SUPABASE_KEY = 'sb_publishable_...';
   ```
⚠️ لا تضع مفتاح `service_role` هنا أبداً.

### 5) الرفع إلى GitHub وتفعيل Pages
1. أنشئ مستودعاً **عاماً** باسم `olympiad-math` في حسابك `osama-salkhdi`.
2. **Add file ← Upload files**، واسحب كل محتويات هذا المجلد (ما عدا `.github`، فلا يُرفع بالسحب).
3. **Settings ← Pages**: المصدر **Deploy from a branch**، الفرع `main`، المجلد `/ (root)`، ثم **Save**.
4. بعد دقيقة يعمل الموقع على `https://osama-salkhdi.github.io/olympiad-math/`.

إن اخترت اسماً آخر للمستودع، عدّل الرابط في `android-app/capacitor.config.json` وفي `android-app/www/offline.html`.

### 6) تطبيق أندرويد (APK)
1. في المستودع: **Actions ← New workflow ← set up a workflow yourself**.
2. سمِّ الملف `android-apk.yml`، والصق فيه محتوى `android-app/android-apk.workflow.yml`، ثم **Commit**.
3. **Actions ← Android APK ← Run workflow**. يستغرق نحو 6 دقائق.
4. رابط التحميل الثابت:
   `https://github.com/osama-salkhdi/olympiad-math/releases/download/android-latest/olympiad-math.apk`

التطبيق غلاف يفتح الموقع الحي، فكل تحديث للموقع يصل إليه دون إعادة تثبيت. يُعاد بناؤه فقط إن غيّرت شيئاً داخل `android-app/`.

لتغيير أيقونة التطبيق: استبدل الصور في `android-app/assets/` (1024×1024) ثم شغّل الـ workflow.

## نسخة لكل اختصاص
الملفات نفسها تصلح لكل الاختصاصات. لكل اختصاص: مستودع GitHub جديد + مشروع Supabase جديد + `js/config.js` خاص به، ثم من **الإعدادات ← التدريب** اختر «اختصاص هذه المنصة».
- الرياضيات تبدأ كل مرحلة بالمحاور الأربعة. بقية الاختصاصات تبدأ بقائمة «المحاضرات» دون محاور.
- من داخل أي مرحلة تستطيع **إضافة محور / قسم** أو تعديله أو حذفه في أي اختصاص.
- ⚠️ الخطة المجانية في Supabase تسمح بمشروعين نشطين فقط لكل حساب، فستة اختصاصات تحتاج ثلاثة حسابات Supabase (أو خطة مدفوعة).

## داخل المرحلة
بعد كلمة السر يرى الطالب تبويبين: **المحاور** (أو **المحاضرات**)، و**أسئلة الدورات والاختبارات التجريبية**. الثاني يطلب كلمة سر المرحلة نفسها مرة ثانية، ثم يعرض مربعين: اختبارات تجريبية، وأسئلة دورات.

**المشاهدة فقط:** الطالب لا يجد زر تنزيل، وتُعطَّل أزرار التصدير داخل ملفات HTML والنقر الأيمن والطباعة. هذا يمنع التنزيل العادي، لكنه لا يمنع تصوير الشاشة، ولا يمنع مستخدماً تقنياً من استخراج الملف من أدوات المتصفح.

## أول استعمال
1. ادخل بحساب `dev`، ومن **الإعدادات** غيّر اسم المنصة وارفع الشعار.
2. من **المستخدمون** أنشئ حسابات المشرفين إن أردت.
3. من **الطلاب ← استيراد طلاب**: ارفع ملف Excel فيه عمود عنوانه «الاسم» (واختيارياً: الاختصاص، المدرسة، الصف، الهاتف). تُولَّد الأرقام الامتحانية والحسابات وكلمات السر.
4. اضغط **بطاقة** بجانب أي طالب لتنزيل صورته أو نسخ نصه. و**تصدير كل البطاقات** يعطيك ملفاً يفتح في Excel.
5. من **المحاضرات العلمية** ادخل المرحلة، ثم **إدارة المرحلة والدخول**: ضع كلمة السر، وافتح المرحلة، وارفع قائمة المسموح لهم (Excel أو PDF) أو اخترهم يدوياً.
6. ارفع الجلسات داخل كل محور، وأسئلة الدورات، وأنشئ الاختبارات التجريبية.

**كيف يدخل الطالب المرحلة؟** يجب أن تجتمع ثلاثة شروط: المرحلة مفتوحة، واسمه في القائمة إن كان الدخول محصوراً بها، وأدخل كلمة السر الصحيحة. عند تغيير كلمة السر يُطلب من الجميع إدخالها من جديد.

**ملاحظة عن ملفات HTML:** تُعرض داخل إطار معزول لحماية حسابات الطلاب، فلا تستطيع الصفحة استعمال `localStorage`. بنوك الأسئلة التي أُعدّت لهذه المنصة تعمل كما هي.

## حدود الخطة المجانية وما يستهلكها

| المورد | الحد | ملاحظة |
|---|---|---|
| قاعدة البيانات | 500MB | تكفي لآلاف الطلاب والاختبارات |
| الملفات | 1GB | **أهم حد.** بنك الأسئلة الكامل نحو 6MB، وPDF المصوَّر قد يبلغ 3–10MB |
| النقل الشهري | 5GB | كل فتح لملف 6MB يستهلك 6MB. 100 طالب يفتحون 8 ملفات شهرياً ≈ 5GB |
| اتصالات لحظية | نحو 200 | يكفي لاختبار يقدّمه 200 طالب معاً |
| التوقف | بعد 7 أيام بلا استخدام | يُعاد تشغيله من لوحة Supabase بضغطة |

نصائح:
- الملف الواحد حدّه 45MB في المنصة، لكن اجعل ملفاتك دون 10MB.
- تحويل PDF إلى HTML يحفظ الصفحات صوراً، فاستعمله للملفات القصيرة (دون 20 صفحة).
- الفيديو والملفات الكبيرة ضعها روابط (Drive / YouTube) داخل وصف الجلسة أو في وظيفة.
- خذ **نسخة احتياطية كاملة** من الإعدادات مرة في الشهر: ZIP فيه كل الجداول (JSON وCSV) وكل الملفات.

## الأمان باختصار
- كل الجداول عليها RLS، والطالب لا يرى ملفات مرحلة لم يدخلها، لا من الواجهة ولا من الخادم.
- كلمات سر المراحل لا تصل إلى متصفح الطالب، والتحقق منها يجري في قاعدة البيانات.
- أسئلة الاختبارات وإجاباتها لا تصل للطالب قبل التسليم، والتصحيح والوقت على الخادم.
- **بطاقات الدخول:** كلمات سر الطلاب المولَّدة تُحفظ نصاً في جدول يقرؤه المشرفون فقط، لتتمكن من إعادة إرسالها. هي أيضاً داخل النسخة الاحتياطية، فاحفظ ملفها في مكان آمن.

## التحديثات لاحقاً
كل تحديث يصلك حزمة ZIP فيها الملفات المتغيرة فقط: ارفعها فوق القديمة من **Upload files**. ملف `js/config.js` لا يدخل في أي حزمة تحديث. وأي تعديل على قاعدة البيانات يأتي ملف SQL منفصلاً آمناً للتشغيل.
